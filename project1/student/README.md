# 项目一：招录招聘公告采集（学生框架）

采集襄阳市人力资源和社会保障局“招录招聘”栏目前 30 页公开公告。栏目入口：<http://rsj.xiangyang.gov.cn/xwzx/zlzp/>。

本框架沿用第 5 次课 `crawler.py` 的结构。作业重点是分页 URL、网页请求、XPath 解析、CSV 保存和主程序调用。简要运行说明和异常处理框架已经提供，不要求编写复杂日志系统或数据预处理功能。

## 需要完成的内容

只完成 [crawler.py](crawler.py) 中以下 TODO：

0. 最开始的采集配置项，包括要采集的栏目入口地址，本次最多采集的页数，相邻两次网页请求之间的等待时间，单次网页请求最长等待时间，将网页原始字节转换为字符串时使用的字符编码
1. `build_url()`：根据页码生成列表页 URL。
2. `fetch_page()`：请求网页、检查状态、保存原始 HTML、返回网页文本。
3. `parse_page()`：用 XPath 提取六个字段。
4. `save_csv()`：按指定列保存 UTF-8 with BOM CSV。
5. `main()`：补齐以上函数的调用、汇总本页记录并保存结果。

`save_summary()`、异常捕获和目录配置已经给出。学生需要阅读并理解其作用，但不需要重新编写。

## 字段要求

| 字段 | 字段含义 | 要求 |
| --- | --- | --- |
| `title` | 公告标题 | 使用链接的完整 `title` 属性，去掉首尾空白 |
| `publish_date` | 公告在列表页显示的发布日期 | 使用列表页显示的日期，格式为 `YYYY-MM-DD`；缺失时留空并说明 |
| `detail_url` | 公告详情页的完整地址 | 将页面真实 `href` 转为绝对 URL |
| `source_url` | 该公告所在列表页的地址 | 保存当前列表页 URL，用于追溯公告来源 |
| `page` | 公告所在列表页的逻辑页码 | 从 1 开始计数，并与 `source_url` 对应 |
| `collected_at` | 程序采集该公告的时间 | 调用教师提供的 `now()` 获得，不等同于发布日期 |

一页公告分布在多个 `ul.news-list` 中，XPath 应选中所有公告，不能只解析第一个列表块。标题、链接或公告列表缺失时，应抛出 `ValueError`，不能返回假数据或把失败当作末页；日期缺失时留空并在运行说明中注明。

## 运行步骤

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe crawler.py
```

先保留 `MAX_PAGES = 1` 调试。检查首页条数、标题、日期和详情链接无误后，将它改成 `30`，再正式运行。

程序使用固定的输出目录，重新运行时会更新原有结果：

```text
data/raw/page_N.html             每个成功请求的原始列表页
data/output/announcements.csv    按列表顺序汇总的六列公告数据
logs/failed_pages.csv            失败页；无失败时只有表头
logs/run_summary.txt             页数、条数和完成状态的简要说明
```

日志只保留最低信息：哪一页失败、失败原因、成功页码和最终条数。遇到 403、429、超时或网页结构变化时停止即可，不需要重试或绕过访问限制。

4. **程序设计**：简要说明 `build_url()`、`fetch_page()`、`parse_page()`、`save_csv()` 四个函数的作用；可以放关键代码截图，不要把整个源文件逐页截图。
5. **单页调试**：设置 `MAX_PAGES = 1`，插入终端运行结果和 CSV 前几条记录截图，说明网页值与采集值是否一致。

9. **实验结论**：说明是否完成 30 页采集、实际成功页数、公告总条数以及人工核对结果。

所有截图应清晰可读，保留能说明问题的窗口、地址或字段。源代码会单独提交，因此报告中无需粘贴完整代码。
